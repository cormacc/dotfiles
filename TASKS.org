Expose a curated subset of home services to the public internet, using the edge Caddy on the Raspberry Pi 4 (task 2d737e59) as the TLS terminator and UniFi as the WAN gateway with port-forward to Caddy. Blocked by the Kanidm task (`2d737e59-b8ff-4fe4-b0e5-f77770e61fd4`), which builds the edge host, its Caddy and the UniFi :443 forward.

Per-service exposure policy (see [[file:design/home-network-infrastructure.org::*Per-service exposure model]]):

| Service    | Public OK? | Reason                                              |
|------------+------------+-----------------------------------------------------|
| Open WebUI | YES        | Has auth; designed for external use                 |
| Vane       | NO         | No auth by design                                   |
| SearXNG    | NO         | Internal backend; no value to expose                |
| Lemonade   | NO         | Compute-abuse risk; raw LLM API                     |

So the initial public surface is **Open WebUI only**.

Design questions for the planner pass:
- Public DNS: `chat.emptycannon.eu` (decided 2026-10-16). DNS moves from GoDaddy to Cloudflare or deSEC in task 2d737e59.
- TLS: ACME DNS-01 (decided 2026-10-16); :80 stays closed.
- UniFi port forward: WAN :443 → edge Pi Caddy (decided 2026-10-16), which proxies to Open WebUI on strix. Verify UniFi firmware version + recent config patterns.
- Caddy vhosts: the edge Caddy serves `chat.emptycannon.eu`; the strix LAN Caddy serves `chat.home.emptycannon.eu`; both front the same Open WebUI backend.
- Open WebUI hardening before exposing: forced strong passwords, disable signup, audit log review, rate-limit at Caddy, geo-block via Caddy if desired.
- Threat model: brute-force on the login form is the dominant risk. Caddy-level rate-limit and fail2ban-equivalent before going live.
- DDNS: handled in task 2d737e59 through the DNS provider API.

Acceptance shape (refine in planner pass):
- `https://chat.emptycannon.eu/` reaches Open WebUI login from any internet client.
- TLS cert is auto-renewing.
- Vane / SearXNG / Lemonade are NOT exposed (negative test from off-tailnet, off-LAN device).
- UniFi forward + Caddy config both checked into NixOS where possible (UniFi probably manual unless using UniFi's API).

Should be promoted to its own change-record via planner once the LAN Caddy task is done and Open WebUI exposure is the current priority.
