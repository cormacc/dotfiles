** Run-time state hygiene (no-littering)

=no-littering= keeps runtime state out of the top level of =~/.config/emacs=. It must load before any mode that reads or writes a state file, because those modes resolve their file variable when enabled: =recentf-mode= enabled first would save to =var/recentf-save.el= but read the empty default path. So this block comes first, and =:ensure (:wait t)= blocks until it has loaded.

#+begin_src emacs-lisp
  (use-package no-littering
    :ensure (:wait t)
    :demand t
    :config
    (setq custom-file (no-littering-expand-etc-file-name "custom.el"))
    (when (file-exists-p custom-file) (load custom-file nil t))
    (no-littering-theme-backups))
#+end_src

Session state (recent files, minibuffer history, cursor position, auto-revert) follows and picks up the =no-littering= paths.

#+begin_src emacs-lisp
(use-package recentf
  :ensure nil
  :init (setq recentf-max-saved-items 200)
  :config (recentf-mode 1))

(use-package savehist
  :ensure nil
  :config (savehist-mode 1))

(use-package saveplace
  :ensure nil
  :config (save-place-mode 1))

(use-package autorevert
  :ensure nil
  ;;Auto-refresh dired, quietly
  :init (setq global-auto-revert-non-file-buffers t
              auto-revert-verbose nil
              ;; Poll instead of inotify: a writer that truncates then writes
              ;; emits two `changed' events, and `auto-revert-notify-handler'
              ;; reverts on the first one (the 2.5s lockout only throttles the
              ;; later ones), so the buffer can be filled from the 0-byte file.
              auto-revert-use-notify nil)
  ;;Auto-refresh file buffers
  :config (global-auto-revert-mode 1))
#+end_src

Embedded from [[https://github.com/magnars/emacsd-reboot/blob/main/settings/fast-startup.el][magnars/emacsd-reboot]].

;; Set garbage collection threshold high for startup
(setq gc-cons-threshold (* 1024 1024 100))

;; Set file-name-handler-alist
(setq file-name-handler-alist-original file-name-handler-alist)
(setq file-name-handler-alist nil)

;; Keep tabs on startup time
(add-hook 'emacs-startup-hook
          (lambda ()
            (message "Emacs ready in %s with %d garbage collections."
                     (format "%.2f seconds"
                             (float-time
                              (time-subtract after-init-time before-init-time)))
                     gcs-done)))

;; Reset to a lower value once startup has completed
(run-with-idle-timer
   5 nil
   (lambda ()
     (setq gc-cons-threshold (* 1024 1024 20))
     (setq file-name-handler-alist file-name-handler-alist-original)
     (makunbound 'file-name-handler-alist-original)))

** Restore open buffers

=SPC q r= (=restart-emacs=) runs =kill-emacs-hook=, where =desktop-save-mode= has installed =desktop-kill=, so saving needs nothing but the mode. =desktop-restore-frames= (default t) carries the window layout, not just the buffer list. Paths come from [[#run-time-state-hygiene-no-littering][no-littering]] (=var/desktop/=), so this block must stay after it.

The built-in path does not work here: =desktop.el= calls =desktop-read= from =after-init-hook=, which is where =init.el= runs =elpaca-process-queues=, so buffers needing an Elpaca package would restore into =fundamental-mode=. Restore on =elpaca-after-init-hook= instead. The built-in entry is guarded by ~(when desktop-save-mode ...)~, so the mode must *not* be on at load time or the desktop is read twice; only =my/restore-session= enables it.

=desktop-save= is t so a restart never asks. =desktop-load-locked-desktop= is ='check-pid=: a clean restart releases the lock, so this only applies after a crash (stale PID, load silently) or with a second live Emacs on the same directory (refuse). The default ='ask= prompts after every crash and, via ~(unless (daemonp) (y-or-n-p ...))~, silently refuses under a daemon. ='check-pid= is only unsafe on a remote =desktop-dirname=; =var/desktop/= is local.

The dashboard covers a fresh start. =my/desktop-available-p= is snapshotted at load time, before anything can write a desktop file, and [[#landing-page][Landing page]] does no startup wiring of its own; otherwise =dashboard-setup-startup-hook= would put =dashboard-initialize= on =emacs-startup-hook= and leave a =*dashboard*= buffer behind a restored layout.

Desktop restores file-backed buffers plus modes with a =desktop-buffer-mode-handlers= entry: Dired yes, Magit no, and the [[#terminal-and-repl-states][Terminal and REPL states]] buffers do not come back.

#+begin_src emacs-lisp
  (defvar my/desktop-available-p nil
    "Non-nil when a saved desktop existed at startup.
Snapshotted before `desktop-save-mode' can write one, so it stays a
statement about the previous session.")

  (use-package desktop
    :ensure nil
    :demand t
    :init
    (setq desktop-save t
          desktop-load-locked-desktop 'check-pid
          desktop-restore-frames t)
    :config
    (setq my/desktop-available-p (file-exists-p (desktop-full-file-name))))

  (defun my/restore-session ()
    "Restore the saved desktop, or build the dashboard when there is none.
Runs from `elpaca-after-init-hook', once every package is installed and
activated, so restored buffers get their real major modes."
    (desktop-save-mode 1)
    (if my/desktop-available-p
        (desktop-read)
      (dashboard-setup-startup-hook)
      (dashboard-insert-startupify-lists)
      (dashboard-initialize)))

  (add-hook 'elpaca-after-init-hook #'my/restore-session)
#+end_src

** Core keybindings - leaders and prefixes
- =SPC= is the global leader in normal/visual/motion states.
- =,= is the local (major-mode) leader.
- =C-SPC= and =C-,= are the insert-state equivalents.
- =SPC m= is bound below as an alias for =,=.

Top-level prefixes are created here. Subject sections add their nested prefixes and leaves beside the commands they expose.

Labels use which-key's keymap-based replacement, not general's =:which-key= keyword: the description lives in the keymap entry instead of being string-matched in ~which-key-replacement-alist~ at display time (general's own recommendation). The two forms:
- a command --- ="k" '("description" . command)=
- a prefix --- ="k" (cons "description" (make-sparse-keymap))=

#+begin_src emacs-lisp
;; Elpaca installs asynchronously -- block here to make sure general.el and evil.el installed
(elpaca-wait)

(general-create-definer my/leader
      :states '(normal visual motion emacs)
      :keymaps 'override
      :prefix "SPC"
      :global-prefix "C-SPC")

(general-create-definer my/local-leader
      :states '(normal visual)
      :prefix ","
      :global-prefix "C-,")

(my/leader
  "SPC" '("M-x" . execute-extended-command)

** Session
:PROPERTIES:
:CUSTOM_ID: session
:END:
Order inside =my/quit-emacs= is load-bearing. =desktop-save-mode= goes off first, which makes the =desktop-kill= entry on =kill-emacs-query-functions= a no-op; only then is the file removed. The other way round hits ~(unless desktop-dirname (read-directory-name ...))~ in =desktop-kill= and turns quitting into a prompt. The file is deleted directly rather than with =desktop-remove=, which nulls =desktop-dirname= and would leave =desktop--on-kill= resolving the lock name against nothing.

An unclean exit still leaves a desktop behind; only a deliberate quit discards the session.

#+begin_src emacs-lisp
  (defun my/quit-emacs ()
    "Quit Emacs, discarding the saved session.
The next launch starts fresh; use \\[restart-emacs] to come back to this one."
    (interactive)
    (desktop-save-mode 0)
    (let ((file (desktop-full-file-name)))
      (desktop-release-lock)
      (when (file-exists-p file) (delete-file file)))
    (save-buffers-kill-terminal))

  (my/leader
    "q q" '("quit emacs" . my/quit-emacs)
    "q r" '("restart emacs" . restart-emacs))
#+end_src

** Expand region
:PROPERTIES:
:CUSTOM_ID: expand-region
:END:

[[https://github.com/magnars/expand-region.el][expand-region]] grows the selection one semantic unit at a time --- symbol, string, inside the delimiters, the sexp, the defun --- where an Evil text object needs the shape named up front. =SPC e= starts it; then =e= expands again, =-= contracts and =0= resets. The repeat key is the last key of the invoking sequence, which is what makes it =e= here; =-= and =0= are the upstream =expand-region-contract-fast-key= and =expand-region-reset-fast-key= defaults (Spacemacs' =V= / =r= remap sits inside their helm-ag branch, so it does not apply).

No Evil wrapper is needed. expand-region activates the mark, Evil's =evil-visual-activate-hook= then enters visual state, and the visual selection matches the unit exactly. Measured on =(defun f (x) (+ x 1))= with point at =x 1=: =SPC e= selects =x=, then =e= gives =+ x 1=, =e= gives =(+ x 1)=, =e= gives =defun f (x) (+ x 1)=; at that point =d= deletes =(+ x 1)= and =c= replaces it. Starting from a selection behaves the same (=v i w SPC e= gives =+ x 1=). While visual state is inclusive, =region-end= reads one character short of the selection --- Evil's operators use =evil-visual-end=, so only code that inspects the region needs to know.

The selection is a live region, so it feeds the next two sections: =SPC s e= takes it as the [[#iedit][iedit]] occurrence, and =SPC s m a= as the [[#multiple-cursors][multiple-cursors]] match.

=evil-iedit-state= also advises expand-region to add "=e= to edit", but expand-region defines the repeat key last, so =e= expands: measured, pressing =e= went from =x= to =+ x 1= with =iedit-mode= still nil. The echo-area hint still advertises it; =SPC s e= is the way in.

#+begin_src emacs-lisp
  (use-package expand-region
    :ensure t
    :commands (er/expand-region))

  (my/leader
    "e" '("expand region" . er/expand-region))
#+end_src

** Simultaneous editing (iedit)
:PROPERTIES:
:CUSTOM_ID: iedit
:END:

[[https://github.com/victorhge/iedit][iedit]] edits every occurrence of a symbol at once, and [[https://github.com/syl20bnr/evil-iedit-state][evil-iedit-state]] wraps it in the two Evil states Spacemacs uses, so =SPC s e= works as it does there.

What starts: from visual state the selection is the occurrence; from normal state it is the thing at point (=iedit-default-occurrence= --- symbol, word, url, email or markup tag); =C-u SPC s e= recovers the occurrence from the last iedit in this buffer, =C-u C-u SPC s e= the last one in any buffer; =M-0 SPC s e= limits the match to the current function.

=iedit state= inherits normal state, so ordinary motions still work. On top: =n= / =N= next and previous occurrence, =gg= / =G= first and last, =0= / =$= start and end of the occurrence, =TAB= toggle the occurrence at point, =D= delete the occurrences, =S= delete them and enter =iedit-insert state=, =p= replace them with the last yank, =F= / =L= restrict the scope to the function or the line, =J= / =K= grow it one line down or up, =#= number the occurrences, =V= hide the lines with no occurrence, =U= up-case and =C-S-u= down-case. =ESC= or =C-g= leaves; from =iedit-insert state=, =ESC= returns to =iedit state= and =C-g= goes straight to normal state.

=iedit= is in the tree already as a [[#clojure][lispy]] dependency, but it is declared here because =iedit-toggle-key-default= must be nil before it loads: iedit otherwise claims the global =C-;= and starts plain =iedit-mode=, outside the Evil state.

=evil-iedit-state= carries a 2014 copy of =iedit-done=, redefined only to stop iedit pushing the occurrence onto the kill ring. iedit has had =iedit-auto-save-occurrence-in-kill-ring= for that since, and its own =iedit-done= has moved on: the copy drops the =iedit-occurrence-type-global= hand-over that =C-u C-u= reads back, drops the =widen= that ends a scope narrowed under =iedit-auto-narrow=, and repeats buffering cleanup that =iedit-lib-cleanup= now does with kmacro support. Loading =iedit= again after the package restores the upstream definition, and the option covers the kill ring.

#+begin_src emacs-lisp
  (use-package iedit
    :ensure t
    :commands (iedit-mode)
    :init
    (setq iedit-toggle-key-default nil
          iedit-auto-save-occurrence-in-kill-ring nil))

  (use-package evil-iedit-state
    :ensure t
    :commands (evil-iedit-state/iedit-mode)
    :config
    ;; Put the upstream `iedit-done' back over the package's stale copy.
    (load "iedit" nil t))

  (my/leader
    "s e" '("iedit occurrences" . evil-iedit-state/iedit-mode))
#+end_src

** Multiple cursors
:PROPERTIES:
:CUSTOM_ID: multiple-cursors
:END:

[[https://github.com/magnars/multiple-cursors.el][multiple-cursors]] puts a real cursor at several places at once, for the cases [[#iedit][iedit]] does not cover: text that differs between the occurrences, one cursor per line of a selection, and numbering or sorting the regions. Bindings follow the Spacemacs =multiple-cursors= layer, whose =mc= backend they are taken from.

multiple-cursors is an Emacs-region tool, not an Evil one, and that decides the workflow. Its entry points test =region-active-p=, and Evil normal state leaves =transient-mark-mode= nil, so =mc/mark-all-like-this= called from normal state fails with "Mark a region to match first". Start from *visual state*:

1. select the text (=v e=, =v i w=, =V j j= for whole lines);
2. =SPC s m a= (or =b=, or =r= for one cursor per line);
3. =ESC= to leave visual state --- the cursors stay;
4. =i=, =I= or =A=, then type: the insertion is mirrored at every cursor;
5. =ESC=, then =C-g= (or =SPC s m q=) to end multiple-cursors editing.

Evil *operators* are the part that does not carry over, because =mc/cursor-specific-vars= tracks 21 variables for each fake cursor and not one of them belongs to Evil. Measured on =foo foo foo= with a cursor on each match: =ciw bar= gives =bar baro baro=, =x= gives =fo o o=, =dw= gives =fobar o bar o bar=. Insert-state typing, =A=, =mc/edit-lines= and =mc/insert-numbers= are all correct. So: iedit for renaming a symbol, multiple-cursors for typing the same new text in several places, and no evil operator in between.

=mc/always-run-for-all= is t, as in the Spacemacs layer. With the default whitelist, mc asks "execute for all cursors?" for every command it does not know, and under Evil almost every command is one it does not know: =mc--default-cmds-to-run-for-all= holds 77 entries and none of them is an Evil command. The cost is that commands are mirrored per cursor, so a leader command that opens a UI runs once per cursor --- hence the additions to =mc/cmds-to-run-once= below, which is also the escape hatch for anything else that misbehaves.

=mc/keymap= is a minor-mode map, and it outranks Evil's state maps: measured with cursors active, =C-g= reaches =mc/keyboard-quit= and =<return>= reaches =multiple-cursors-mode= in both normal and insert state. That =<return>= binding ends the session instead of inserting a newline, and only in a graphical frame --- a terminal sends =RET=, which mc does not bind. It is unbound here, so RET inserts a newline at every cursor in either kind of frame, and =C-g= remains the way out. =ESC= is left alone: bound in =mc/keymap= it would shadow Evil's own insert-state exit.

[[#run-time-state-hygiene-no-littering][no-littering]] already points =mc/list-file= at =var/mc-list.el=, so the whitelist answers do not land at the top of =~/.config/emacs=.

#+begin_src emacs-lisp
  (use-package multiple-cursors
    :ensure t
    :commands (mc/mark-all-dwim mc/mark-all-like-this mc/mark-more-like-this-extended
               mc/edit-lines mc/insert-letters mc/insert-numbers mc/mark-sgml-tag-pair
               mc/sort-regions mc/reverse-regions set-rectangular-region-anchor
               mc/keyboard-quit)
    :init
    (setq mc/always-run-for-all t)
    :config
    ;; RET types a newline at every cursor; C-g ends the session.
    (keymap-unset mc/keymap "<return>" t)
    ;; Commands that open a UI, and so must not run once per cursor.
    (dolist (cmd '(consult-line consult-buffer consult-ripgrep consult-recent-file
                   embark-act magit-status project-find-file project-switch-project
                   eca eca-chat-toggle-window my/quit-emacs restart-emacs))
      (add-to-list 'mc/cmds-to-run-once cmd)))

  (my/leader
    "s m"   (cons "multiple cursors" (make-sparse-keymap))
    "s m a" '("mark all dwim" . mc/mark-all-dwim)
    "s m b" '("mark all like this" . mc/mark-all-like-this)
    "s m m" '("mark more (extended)" . mc/mark-more-like-this-extended)
    "s m r" '("one cursor per line" . mc/edit-lines)
    "s m q" '("stop cursors" . mc/keyboard-quit)
    "s m s"   (cons "specials" (make-sparse-keymap))
    "s m s l" '("insert letters" . mc/insert-letters)
    "s m s m" '("mark sgml tag pair" . mc/mark-sgml-tag-pair)
    "s m s n" '("insert numbers" . mc/insert-numbers)
    "s m s r" '("rectangular anchor" . set-rectangular-region-anchor)
    "s m s s" '("sort regions" . mc/sort-regions)
    "s m s t" '("reverse regions" . mc/reverse-regions))
#+end_src

** Indentation
:PROPERTIES:
:CUSTOM_ID: indentation
:END:

=indent-for-tab-command= is the single context-aware entry point: it delegates to the buffer-local =indent-line-function=, and to =indent-region= when a region is active. =tab-always-indent= is =t= ([[#defaults][Defaults]]) rather than the more usual ='complete=, so TAB re-indents the line wherever point sits, instead of completing once the line is already indented. [[#corfu][corfu]] pops up by itself after two characters, and the global =M-TAB= (=completion-at-point=) covers an explicit request.

Where the level comes from, per buffer:

- =*-ts-mode= (nix, C, python, and code blocks in markdown) --- =treesit-indent=, i.e. the nesting depth of the node at point in the syntax tree.
- Lisps --- =lisp-indent-line= / =clojure-indent-line=, from the sexp nesting and each symbol's indent spec.
- Org --- =org-indent-line=, aligned to the enclosing headline, list item or block. TAB stays =org-cycle=: with =org-cycle-emulate-tab= at its default =t=, =org-cycle= calls the /global/ TAB binding when point is off a headline, so the same =indent-for-tab-command= runs there.
- =markdown-ts-mode= --- TAB is =markdown-ts-outline-cycle= (visibility on a headline, nothing elsewhere), =markdown-ts-table-next-cell= in a table, and =indent-for-tab-command= in a fenced code block, where the embedded language's tree-sitter rules apply.

Eglot adds no indentation: LSP has document and range formatting only, with no per-line indent request, so server-side layout stays on =, == (=eglot-format-buffer=) in [[#eglot][eglot]].

Evil leaves TAB out of normal state, so without a binding a line can only be re-indented from insert state. =<tab>= is bound instead of =TAB=: the two are distinct events in a graphical frame, so =C-i= keeps =evil-jump-forward= (=evil-want-C-i-jump= is t by default). A terminal frame cannot tell them apart, and there =TAB= jumps rather than indents; =evil-indent= (===) is the fallback in either frame.

=prog-mode-map= scopes it to programming buffers, so markup modes keep the TAB behaviour described above, and any major mode that binds =<tab>= itself still wins over this.

** File manager (dirvish)
:PROPERTIES:
:CUSTOM_ID: dirvish
:END:

[[https://github.com/alexluigit/dirvish][dirvish]] is a session layer over Dired, not a replacement major mode. =dirvish-override-dired-mode= advises seven Dired entry points (=dired-noselect=, =dired--find-file=, =wdired-change-to-dired-mode= and four others), and =dirvish--setup-dired= calls ~(use-local-map dirvish-mode-map)~; the buffer stays in =dired-mode=. So every Dired buffer gains the attributes, preview pane and mode line, and no separate =dirvish-mode= exists.

=:demand t= rather than deferred: the override has to be installed before =my/restore-session= runs on =elpaca-after-init-hook= ([[#restore-open-buffers][Restore open buffers]]), or the Dired buffers that =desktop= restores come back as plain Dired.

=dired-listing-switches= uses long flag names on purpose. =dirvish-ls-switches-menu= and =dirvish-quicksort= decompose this string, and the short forms (=-A=, =-v=) defeat that. GNU =ls= is required; Emacs 31 already selects =gls= on macOS when it is installed, so =insert-directory-program= needs no setting here.

=dirvish-quick-access-entries= is set with =:custom=, not =setq=: its =:set= function re-evaluates the =dirvish-quick-access= transient prefix, so a plain assignment leaves the old menu in place.

Every Evil binding goes on =dired-mode-map=, never on =dirvish-mode-map=. =evil-get-auxiliary-keymap= resolves a state's bindings with ~(lookup-key map [normal-state])~, and =lookup-key= follows the parent chain, so one auxiliary keymap on =dired-mode-map= serves both maps and merges with what evil-collection's =dired= module already binds there. An auxiliary keymap on the child would be found first and take the parent's out of reach. evil-collection 3.0.1 ships no =dirvish= module and needs none.

The single-letter Dired keys are evil-collection's (=a=, =o=, =r=, =^= are all taken), so the transient menus sit behind the local leader, as they do for org, markdown and eglot. =<tab>= toggles a subtree; =TAB= stays unbound so =C-i= keeps =evil-jump-forward= in a terminal frame ([[#indentation][Indentation]]).

=q= is re-bound because evil-collection maps it to =quit-window= (its =quit= theme entry, =:key "q"=).

Preview helpers (=vipsthumbnail=, =ffmpegthumbnailer=, =mediainfo=, =pdftoppm=, =magick=) come from =home.packages= in [[file:~/dotfiles/editors/emacs/emacs.nix][emacs.nix]]; dirvish warns once per missing program. =fd= is =programs.fd.enable= in =shell/shell.nix= and backs =dirvish-large-directory-threshold=.

Grammars are not bundled with Emacs or managed by Nix here. Install once per machine, from a running Emacs:

* LLM
** ECA

[[https://github.com/editor-code-assistant/eca-emacs][eca-emacs]] (MELPA =eca=), client for the [[https://github.com/editor-code-assistant/eca][ECA]] agent server.

- nixpkgs has no =eca= package, so the client downloads the server itself. =no-littering= already points =eca-server-install-path= at =var/eca/=.
- No API keys are exported here: use =/login= in the chat.  An API key in the environment overrides a subscription login and bills the API.
- =evil-collection= has an =eca= module (=RET= submits in normal state).  The chat also starts in insert state; =evil-insert-state-map= leaves =RET= alone.
- =markdown-mode= comes in as a dependency and autoloads a =.md= entry ahead of [[#markdown][markdown-ts-mode]].  =treesit-auto= remaps it back once the =markdown= grammar is installed; until then =.md= opens in =markdown-mode=.
- Bindings sit outside =use-package= (as for Magit) because the package is autoloaded on first command.  =eca-transient-menu= has no autoload cookie, so it is left on its own =C-c .= in ECA buffers.

#+begin_src emacs-lisp
  (use-package eca
    :ensure t
    :config

    (evil-set-initial-state 'eca-chat-mode 'insert))

    "a !" '("next chat needing attention" . eca-chat-go-to-next-attention)
    "a i" '("inline prompt" . eca-chat-inline-prompt)
    "a r" '("rewrite region" . eca-rewrite)
    "a f" '("add file/region as context" . eca-chat-add-context-to-user-prompt)
    "a m" '("select model" . eca-chat-select-model)
    "a g" '("select agent" . eca-chat-select-agent)
    "a ," '("settings" . eca-settings)

** Nix

[[https://github.com/nix-community/nix-ts-mode][nix-ts-mode]] (nix-community, MELPA); Emacs 31.1 ships no Nix mode and no =.nix= entry in =auto-mode-alist=.
