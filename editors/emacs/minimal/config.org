#+AUTHOR: Cormac Cannon
#+PROPERTY: header-args:emacs-lisp :results silent
#+STARTUP: overview

A literate, Evil-based Emacs configuration.
Deliberately small enough to read end to end.

Loaded by =init.el=, which explicitly tangles this file to =config.el= inside =~/.config/emacs= (runtime state, never the dotfiles repository).
Packages come from [[https://github.com/progfolio/elpaca][Elpaca]]; =org= itself is the built-in version, so no second =org= is ever loaded.

Sources live in =dotfiles/editors/emacs/minimal/= and are symlinked out of store, so an edit here takes effect on the next =emacs= launch.

** Run-time state hygiene (no-littering)
=no-littering= keeps runtime state out of the top level of =~/.config/emacs=.
It *must* load before any mode that reads or writes a state file, because those
modes resolve their file variable when the mode is enabled: enabling
=recentf-mode= before =no-littering= repoints =recentf-save-file= gives a
session that saves to =var/recentf-save.el= but reads the (empty) default path.
So this block comes first, and =:ensure (:wait t)= blocks until it has actually
loaded.

#+begin_src emacs-lisp
  (use-package no-littering
    :ensure (:wait t)
    :demand t
    :config
    (setq custom-file (no-littering-expand-etc-file-name "custom.el"))
    (when (file-exists-p custom-file) (load custom-file nil t))
    (no-littering-theme-backups))
#+end_src

Session state: recent files, minibuffer history, cursor position, and
auto-revert of files changed on disk.  All of these now pick up the
=no-littering= paths set above.

#+begin_src emacs-lisp
  (use-package recentf
    :ensure nil
    :init (setq recentf-max-saved-items 200)
    :config (recentf-mode 1))

  (use-package savehist
    :ensure nil
    :config (savehist-mode 1))

  (use-package saveplace
    :ensure nil
    :config (save-place-mode 1))

  (use-package autorevert
    :ensure nil
    :init (setq global-auto-revert-non-file-buffers t
                auto-revert-verbose nil)

** Optimisation

Embedded from [[https://github.com/magnars/emacsd-reboot/blob/main/settings/fast-startup.el][magnars/emacsd-reboot]].

#+begin_src emacs-lisp

;; Set garbage collection threshold high for startup
(setq gc-cons-threshold (* 1024 1024 100))

;; Set file-name-handler-alist
(setq file-name-handler-alist-original file-name-handler-alist)
(setq file-name-handler-alist nil)

;; Keep tabs on startup time
(add-hook 'emacs-startup-hook
          (lambda ()
            (message "Emacs ready in %s with %d garbage collections."
                     (format "%.2f seconds"
                             (float-time
                              (time-subtract after-init-time before-init-time)))
                     gcs-done)))

;; Reset to a lower value once startup has completed
(run-with-idle-timer
   5 nil
   (lambda ()
     (setq gc-cons-threshold (* 1024 1024 20))
     (setq file-name-handler-alist file-name-handler-alist-original)
     (makunbound 'file-name-handler-alist-original)))
#+end_src

* Keybindings
** general

=general.el= supplies the =SPC= leader and the =,= local leader.  =:ensure
(:wait t)= is required because later blocks use general's own macros while the
init file is still being evaluated.

*** Leader definers

- =SPC= is the global leader in normal/visual/motion states, bound in general's
  override keymap so no major mode can shadow it.  =C-SPC= is the insert-state
  equivalent.
- =,= is the local (major-mode) leader.  It is defined per mode map, so the
  same key does something different in Clojure and in Org.
- =SPC m= is an alias for =,=: it simulates the =,= key, which then resolves in
  whatever maps the current buffer has.

#+begin_src emacs-lisp
  (use-package general
    :ensure (:wait t)
    :demand t
    :config
    (general-evil-setup)

    (general-create-definer my/leader
      :states '(normal visual motion emacs)
      :keymaps 'override
      :prefix "SPC"
      :global-prefix "C-SPC")

    (general-create-definer my/local-leader
      :states '(normal visual)
      :prefix ","
      :global-prefix "C-,"))
#+end_src

#+begin_src emacs-lisp
  (elpaca-wait)
#+end_src

*** which-key

Built into Emacs since 30, so no package is installed.  It renders the labels
attached to each prefix below.

Labels use which-key's *keymap-based replacement*, not general's =:which-key=
keyword.  general's own documentation recommends this: keymap-based
replacement is more performant and correct, because the description lives in
the keymap entry itself rather than in ~which-key-replacement-alist~, where it
has to be matched by string at display time.  The two forms are:

- a command --- ="k" '("description" . command)=
- a prefix --- ="k" (cons "description" (make-sparse-keymap))=, written
  unquoted because a fresh keymap object cannot be a literal.  The prefix line
  must come *before* its sub-bindings, or the new keymap replaces the
  populated one.  Re-evaluating one block therefore resets that block's
  prefixes: =SPC b= and =SPC f= gain further entries in the consult block, so
  re-evaluate that block too (or just restart) after re-evaluating the global
  table.

The one remaining =:which-key= below belongs to ~general-simulate-key~, where
it is a function argument rather than a definition keyword.

~which-key-replacement-alist~ remains the right tool for the one case
keymap-based replacement cannot express: rewriting the *key* text rather than
the description.  The single example is the winum row collapse, which lives
with winum in [[#windows][Windows]].

#+begin_src emacs-lisp
  (use-package which-key
    :ensure nil
    :init
    (setq which-key-idle-delay 0.3
          which-key-sort-order 'which-key-key-order-alpha)
    :config
    (which-key-mode 1))
#+end_src

*** Leader skeleton

The compatibility contract: every prefix the leader offers, and nothing else.
Anything not listed here or in a section below is deliberately absent.

Top-level prefixes are created here.  Subject sections add their nested
prefixes and leaves after this block, beside the commands they expose.

The =SPC SPC= and help leaves stay here because they belong to the leader
itself.

#+begin_src emacs-lisp
  (my/leader
    "SPC" '("M-x" . execute-extended-command)
    "h"   (cons "help" help-map)

    ;; Prefixes only.  Leaves live in the section named after each subject:
    ;; Session, Windows, Buffers, Files, Jump, Completion, Git, Project, UI.
    "q"   (cons "quit" (make-sparse-keymap))
    "w"   (cons "windows" (make-sparse-keymap))
    "b"   (cons "buffers" (make-sparse-keymap))
    "f"   (cons "files" (make-sparse-keymap))
    "f e" (cons "emacs config" (make-sparse-keymap))
    "j"   (cons "jump" (make-sparse-keymap))
    "s"   (cons "search" (make-sparse-keymap))
    "g"   (cons "git" (make-sparse-keymap))
    "p"   (cons "project" (make-sparse-keymap))
    "t"   (cons "toggles" (make-sparse-keymap)))
#+end_src

=SPC m= re-dispatches the =,= key so the local-leader menu is reachable from
the global leader.  Defined after the table because =general-simulate-key=
returns a command that must exist when the binding is made.

#+begin_src emacs-lisp
  (my/leader
    "m" (general-simulate-key "," :which-key "local leader"))
#+end_src

** Evil

Vim editing everywhere, with =evil-collection= supplying third-party bindings
and =evil-surround= for =cs"'=-style edits.

=evil-want-keybinding= must be nil before =evil= loads for =evil-collection= to
take over.  =undo-redo= is Emacs 28+ native undo, so no =undo-tree= is needed.

#+begin_src emacs-lisp
  (use-package evil
    :ensure t
    :demand t
    :init
    (setq evil-want-integration t
          evil-want-keybinding nil
          evil-want-C-u-scroll t
          evil-want-Y-yank-to-eol t
          evil-undo-system 'undo-redo
          evil-respect-visual-line-mode t
          evil-split-window-below t
          evil-vsplit-window-right t
          evil-search-module 'evil-search)
    :config
    (evil-mode 1))

  (use-package evil-collection
    :ensure t
    :after evil
    :demand t
    :config
    (evil-collection-init))

  (use-package evil-surround
    :ensure t
    :after evil
    :demand t
    :config
    (global-evil-surround-mode 1))
#+end_src

* Layout and file management
** Windows
:PROPERTIES:
:CUSTOM_ID: windows
:END:

=winum= numbers the windows so =SPC 1= .. =SPC 0= jump directly; =winner=
provides the undo history behind =SPC w u=.  The rest of =SPC w= is built-in
and evil window motion.

Ten near-identical which-key rows are noise, so the =window 1= row is
relabelled to cover the whole range and the other nine are hidden.  A
replacement of =t= (anything that is not a cons) makes which-key drop the
binding from the popup.  The rules match on the *description* the keymap
carries --- "window 1", "window 2", ... --- so they stay correct for both the
=SPC= and =C-SPC= leaders.  This is the one job keymap-based replacement
cannot do, because it rewrites the key text rather than the description.

#+begin_src emacs-lisp
  (use-package winum
    :ensure t
    :demand t
    :init
    (setq winum-auto-setup-mode-line nil
          winum-scope 'frame-local)
    :config
    (winum-mode 1))

  (use-package winner
    :ensure nil
    :config
    (winner-mode 1))

  (defun my/toggle-maximize-window ()
    "Maximize the selected window, or restore the previous layout."
    (interactive)
    (if (and (= 1 (length (window-list)))
             (assq ?_ register-alist))
        (jump-to-register ?_)
      (window-configuration-to-register ?_)
      (delete-other-windows)))

  (my/leader
    "w b" '("Goto minibuffer" . switch-to-minibuffer)
    "w v" '("split right" . split-window-right)
    "w s" '("split below" . split-window-below)
    "w d" '("delete" . delete-window)
    "w m" '("maximize toggle" . my/toggle-maximize-window)
    "w w" '("other window" . other-window)
    "w h" '("focus left" . evil-window-left)
    "w j" '("focus down" . evil-window-down)
    "w k" '("focus up" . evil-window-up)
    "w l" '("focus right" . evil-window-right)
    "w H" '("move left" . evil-window-move-far-left)
    "w J" '("move down" . evil-window-move-very-bottom)
    "w K" '("move up" . evil-window-move-very-top)
    "w L" '("move right" . evil-window-move-far-right)
    "w =" '("balance" . balance-windows)
    "w u" '("winner undo" . winner-undo)

    "1"   '("window 1" . winum-select-window-1)
    "2"   '("window 2" . winum-select-window-2)
    "3"   '("window 3" . winum-select-window-3)
    "4"   '("window 4" . winum-select-window-4)
    "5"   '("window 5" . winum-select-window-5)
    "6"   '("window 6" . winum-select-window-6)
    "7"   '("window 7" . winum-select-window-7)
    "8"   '("window 8" . winum-select-window-8)
    "9"   '("window 9" . winum-select-window-9)
    "0"   '("window 0" . winum-select-window-0-or-10))

  ;; Show one "0..9" row for the winum window pickers instead of ten rows.
  ;; The key text is rewritten in place, so any leader prefix is preserved;
  ;; `which-key--extract-key' displays the last space-delimited token.
  (add-to-list 'which-key-replacement-alist
               '((" 1\\'" . "\\`window 1\\'") . (" 0..9" . "select window")))
  (add-to-list 'which-key-replacement-alist
               '((nil . "\\`window [02-9]\\'") . t))
#+end_src

* UI

** Fonts

[[https://github.com/rainstormstudio/nerd-icons.el][nerd-icons]] supplies the glyphs that =dashboard= and the completion UIs draw.

=:ensure t= is *not* optional here.  =init.el= leaves =use-package-always-ensure=
at nil and sets =use-package-always-defer= to nil, so a bare =(use-package
nerd-icons)= expands to a plain =(require 'nerd-icons nil nil)= with no Elpaca
order behind it --- the package is never installed and the require aborts the
rest of =config.el=.  No other package pulls it in: =dashboard= declares only
=((emacs "27.1"))=.

The glyphs need the =Symbols Nerd Font Mono= family --- the default value of
=nerd-icons-font-family=.  =M-x nerd-icons-install-fonts= drops it in
=~/.local/share/fonts=, outside Nix's control; add =nerd-fonts.symbols-only= to
=dev/dev.nix= to have Home Manager own it instead.

#+begin_src emacs-lisp
  (use-package nerd-icons
    :ensure t
    :demand t)
#+end_src

** Themes
[[https://protesilaos.com/emacs/ef-themes][ef-themes]] with a light/dark pair behind =SPC t T=. The default face uses the =Aporetic Sans Mono= family supplied by =aporetic-bin=.  =SPC t= collects the
display toggles.

#+begin_src emacs-lisp
  (use-package ef-themes
    :ensure t
    :demand t
    :config
    ;; Set after load: `ef-themes-to-toggle' and `ef-themes-mixed-fonts' are
    ;; defvaralias-es onto the modus-themes variables, and assigning them
    ;; before the alias exists warns about overwriting the aliased value.
    (setq ef-themes-to-toggle '(ef-maris-light ef-maris-dark)
          ef-themes-mixed-fonts t)
    (load-theme 'ef-maris-light :no-confirm)
    ;; Family name verified from the packaged font's metadata.
    (set-face-attribute 'default nil :family "Aporetic Sans Mono"))

  (defun my/toggle-theme ()
    "Toggle between the light and dark `ef-themes' pair."
    (interactive)
    (ef-themes-toggle))

  (my/leader
    "t n" '("line numbers" . display-line-numbers-mode)
    "t t" '("truncate lines" . toggle-truncate-lines)
    "t T" '("theme light/dark" . my/toggle-theme))
#+end_src

** Landing page

[[https://github.com/emacs-dashboard/dashboard][dashboard]] as the startup buffer.  The two =elpaca-after-init-hook= entries are
the upstream Elpaca recipe: Elpaca installs asynchronously, so the dashboard
must be built after the queues drain rather than at =after-init-time=.

The options are set in =:init=, before =dashboard-setup-startup-hook= reads
them.  Installing [[#fonts][nerd-icons]] is necessary but not sufficient for icons:
=dashboard-icon-type= is a defcustom gated on the two =set-*-icons= flags, so
it evaluates to nil unless at least one of them is already non-nil.

#+begin_src emacs-lisp
  (use-package dashboard
    :ensure t
    :demand t
    :init
    (setq dashboard-center-content t
          dashboard-vertically-center-content t
          dashboard-set-heading-icons t
          dashboard-set-file-icons t)
    :config
    (add-hook 'elpaca-after-init-hook #'dashboard-insert-startupify-lists)
    (add-hook 'elpaca-after-init-hook #'dashboard-initialize)
    (dashboard-setup-startup-hook))
#+end_src

** embark and wgrep

=C-.= acts on the thing at point, including the current minibuffer candidate.
=embark-export= from a =consult-ripgrep= session produces a grep buffer;
=wgrep= then makes it editable with =C-c C-p=, and =C-c C-c= writes the edits
back to the files.

#+begin_src emacs-lisp
  (use-package embark
    :ensure t
    :demand t
    :init
    (setq prefix-help-command #'embark-prefix-help-command)
    :bind (("C-." . embark-act)

** Tree-sitter

Grammars are *not* bundled with Emacs and are not managed by Nix here.  Install
them once per machine from a running Emacs:

- =M-x treesit-install-language-grammar= for a single language, or
- =M-x treesit-auto-install-all= for every grammar =treesit-auto= knows about, or
- =M-x markdown-ts-mode-install-parsers= for the =markdown= + =markdown-inline=
  pair that =markdown-ts-mode= needs.

They land in =~/.config/emacs/tree-sitter/=, i.e. runtime state.
=treesit-auto= then remaps a language's classic mode to its =*-ts-mode= only
when the grammar is actually present, so a missing grammar degrades to the
classic mode instead of erroring.

=treesit-auto-add-to-auto-mode-alist= is called with *no* argument on purpose:
that registers only grammars satisfying =treesit-ready-p=.  Passing ='all=
would overwrite Emacs 31's own =\.rs\' → rust-ts-mode-maybe= style entries,
whose whole job is to degrade when the grammar is missing, and every visit to
an uninstalled language would prompt to install a grammar instead.

=treesit-language-source-alist= starts empty; built-in language files push their
own entry when they load (=sh-script.el= adds =bash=, for instance).
=treesit-auto= only /let-binds/ its recipe list inside =M-x
treesit-auto-install-all=, so a plain =M-x treesit-install-language-grammar=
sees nothing for a language whose mode came from a package.  The entries below
are the grammars this config wires a mode for by hand (see =* Nix=).

#+begin_src emacs-lisp
  (use-package treesit
    :ensure nil
    :config
    ;; src/ is at the repository root for this grammar, so URL alone is enough.
    (add-to-list 'treesit-language-source-alist
                 '(nix "https://github.com/nix-community/tree-sitter-nix")))

  (use-package treesit-auto
    :ensure t
    :demand t
    :init
    (setq treesit-auto-install 'prompt)
    :config
    (treesit-auto-add-to-auto-mode-alist)
    (global-treesit-auto-mode 1))
#+end_src

** Nix

This repository is a Nix flake, so =.nix= gets a real mode.  [[https://github.com/nix-community/nix-ts-mode][nix-ts-mode]]
(nix-community, MELPA) is the tree-sitter mode for it; Emacs 31.1 ships no Nix
mode of its own and no =.nix= entry in =auto-mode-alist=.

It needs the =nix= grammar (see Prog ▸ Tree-sitter): =M-x
treesit-install-language-grammar= then =nix=, or =M-x
treesit-auto-install-all=, which knows the same grammar URL.  Without it
=nix-ts-mode= still loads -- its body is guarded by =treesit-ready-p= -- but
degrades to a plain =prog-mode= with a warning rather than prompting or
erroring.

Fontification runs at the stock =treesit-font-lock-level= 3, i.e. comments,
builtins, constants, strings, paths, URIs, numbers, operators, keywords,
function calls and definitions -- the same level every other =*-ts-mode= here
uses.  nix-ts-mode also defines a decorative level 4 (parameters, properties,
brackets, delimiters, the =@= pattern); raise =treesit-font-lock-level= if you
want it, bearing in mind the variable is global.

#+begin_src emacs-lisp
  (use-package nix-ts-mode
    :ensure t
    :mode "\\.nix\\'")
#+end_src
