* Intent
Self-host NetBird on the Raspberry Pi 4 edge host, with Kanidm as its IdP, and enrol every host and family device, so internal home services are reachable off-LAN without public exposure and network access follows Kanidm groups.

* Summary
*Level:* production · *Tests:* smoke · *Docs:* inline

Draft. NetBird server (=services.netbird.server=) at =netbird.emptycannon.eu= on the edge host, behind the edge Caddy from the Kanidm task. Clients: =services.netbird.clients.<name>= on NixOS, =services.netbird= on nix-darwin, the distribution package on Arch. Blocked by the Kanidm task (2d737e59). Design decisions are recorded in =design/home-network-infrastructure.org=.

** Scope
*** In scope
- NetBird management, signal, dashboard, relay and coturn on the edge host, with Kanidm as the OIDC provider.
- UniFi forwards for the NetBird UDP ports (coturn udp/3478 and the relay).
- Access policies driven by Kanidm groups (JWT group sync), default deny.
- A shared NixOS client mixin; strix and other servers join with setup keys.
- Workstation and phone enrolment: NixOS laptops, the Mac (nix-darwin), Arch hosts, at least one family phone.
- One service URL that works on and off the LAN, used by pi's =mcp-searxng= (=agents/pi/mcp.json=) and listed in Lemonade's =allowedOrigins= on strix.
- Relevant contract: =design/home-network-infrastructure.org= (per-service exposure model).
*** Out of scope
- Kanidm itself (task 2d737e59).
- NetBird SSH (roadmap Phase 5, with Kanidm Unix integration).
- Public exposure of any service (task 5f53ceac).
- LAN Caddy and internal service names (task 0e5c627e).

** Acceptance
*** Core functionality
- [ ] A Kanidm user logs in to the NetBird dashboard at =https://netbird.emptycannon.eu=.
- [ ] strix joins with a setup key read from a file outside the Nix store.
- [ ] From an off-LAN laptop on NetBird, a SearXNG JSON query on strix returns results.
- [ ] From an off-LAN laptop on NetBird, Open WebUI loads.
- [ ] From an off-LAN laptop on NetBird, Lemonade =/api/v1/models= returns models.
- [ ] From an off-LAN laptop on NetBird, Vane loads.
- [ ] pi's =mcp-searxng= works off-LAN with the same =SEARXNG_URL= it uses on the LAN.
- [ ] A family phone enrols through the NetBird app with a Kanidm login.
- [ ] Removing a user from the Kanidm group that a policy names removes that user's access.
*** Edge cases
- [ ] Two NetBird peers on the same LAN connect directly, not through the relay.
- [ ] Established peer connections keep working while the edge host restarts.
*** Anti-criteria
- [ ] Must not: expose Vane, SearXNG or Lemonade publicly (closed from an off-LAN device that is not on NetBird).
- [ ] Must not: put setup keys, coturn passwords or OIDC client secrets in the Nix store or git.

** Decisions
- Decisions shared with the wider network design live in =design/home-network-infrastructure.org=: NetBird (rejected Headscale, Tailscale SaaS), Kanidm as IdP, the Pi 4 edge host.

** Risks
- NixOS module lag :: =services.netbird.server= runs the older multi-service layout and does not expose upstream's built-in IdP or combined server; accepted because Kanidm is the IdP.
- Kanidm compatibility :: NetBird does not list Kanidm as a tested IdP; the Kanidm task's spike must pass before this work starts.
