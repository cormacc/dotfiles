* Intent
Remove the Hermes agent from every host configuration, so that the NAS runs only declarative services that a person or a coding agent operates directly. The owner abandoned Hermes on 2026-10-21.

* Summary
*Level:* production · *Tests:* smoke · *Docs:* inline

The dotfiles configuration no longer references the =hermes-agent= flake input, overlay, NixOS module, package or Homebrew cask. On =nas=, the former =homelab-agent.nix= module is now =hosts/odroid-h4/homelab-health.nix= and keeps only the =homelab-health= user, timer and service. The disabled Python =homelab-unifi-watch= units are also removed; the Babashka collector arrives in its own change (homelab-agent task =ebd571e3=).

** Scope
*** In scope
- =flake.nix=: the =hermes-agent= input, its overlay in =linuxOverlays=, and its NixOS module on =nas= and =xps15=. =flake.lock= drops the input and its transitive nodes.
- =hosts/odroid-h4/=: the =services.hermes-agent= block, the =/opt/homelab-agent= mount, the =/var/lib/hermes= sandbox exclusion, and the disabled Python UniFi service, timer and tmpfiles rules.
- =dev/dev-linux.nix= (=hermes-agent= package), =darwin-configuration.nix= (=hermes-desktop= cask), comments in =agents.nix=, =README.org=, =design/home-network-infrastructure.org=.
- One NAS switch, its verification, then a separately approved clean-up of the Hermes host state.
- =xps15= and the MacBook pick up the change at their next ordinary switch.
*** Out of scope
- Restructuring the homelab-agent repository (its task =11089b66=).
- The Babashka UniFi collector and the =homelab-health= port to Babashka.
- =hosts/odroid-h4/sudo-authorization.nix=: kept; only its comment changed.
- Deleting the old remote branches (=homelab/unifi-native-rehearsal-20261016= and the UniFi draft archive branches).
- Compose services, monitoring, MooseFS and the UniFi controller.

** Acceptance
*** Core functionality
- [X] =nas=, =xps15=, =darwinConfigurations.Cormacs-MacBook-Air= and =homeConfigurations.default= evaluate to a derivation.
- [X] The evaluated =nas= config has no =hermes-agent= service, no =hermes= user or group, and no =homelab-unifi-watch= service or timer.
- [X] The evaluated =nas= config keeps =homelab-health.service= and =homelab-health.timer=.
- [X] =flake.lock= drops only =hermes-agent= from the root inputs; every other root input keeps its locked revision.
- [ ] After the NAS switch, =systemctl status hermes-agent.service= reports that the unit is not found.
- [ ] After the NAS switch, =homelab-health.timer= is active and no unit is failed.
- [ ] After the NAS switch, the Compose units have the same active state as before the switch.
*** Edge cases
- [ ] A failed NAS switch is rolled back with =sudo nixos-rebuild switch --rollback= before any clean-up.
*** Anti-criteria
- [ ] Must not: delete =/var/lib/hermes=, the =hermes-agent= container or image, or =~cormacc/.hermes= without a recorded listing and separate approval.
- [ ] Must not: change Compose services, monitoring, MooseFS or =/var/lib/homelab-unifi/= contents in the same switch.

** Decisions
- Start from =origin/main=, not from the deployed branch :: every commit on =homelab/unifi-native-rehearsal-20261016= is Hermes or Hermes-built UniFi work.
  Rejected:
  - Revert commits on the old branch: keeps a long history of discarded work on the deployed line.
- Remove the disabled Python UniFi units in this switch :: the Python collector is discarded; leaving disabled units deployed until the Babashka collector arrives has no value.
  Rejected:
  - Keep them until the replacement switch: one more switch carries dead code.
- Keep the global sudo ticket (=sudo-authorization.nix=) :: one password prompt in the operator's terminal covers an agent's terminal-less SSH sessions for five minutes, which keeps friction low. =cormacc= is already in the =docker= group, so the ticket adds little privilege.
  Rejected:
  - Remove it: the operator must type every privileged command.
  - Passwordless sudo: removes the human gate.
- Rename =homelab-agent.nix= to =homelab-health.nix= :: only the health check remains in it.

** Gotchas
- The NAS runs a generation built from =homelab/unifi-native-rehearsal-20261016= (=980acb5=), according to the UniFi handover document on that branch. Not rechecked. The switch therefore also drops that branch's Hermes source patch and its =homelab-unifi.nix= units.
- Removing the Hermes NixOS module stops =hermes-agent.service= (its =preStop= runs =docker stop=). The container, its image, =/var/lib/hermes= (including the =.gc-root= links that keep Hermes store paths alive) and the =~cormacc/.hermes= symlink remain until the clean-up task.
- =darwin-configuration.nix= sets =homebrew.onActivation.cleanup = "uninstall"=, so the next =darwin-rebuild switch= uninstalls the Hermes Desktop cask. It keeps the app data.
- This checkout has many pre-existing stashes that belong to the owner. Do not use =git stash= to take a baseline; evaluate =git+file://…?rev=<rev>&submodules=1= instead.

** Risks
- NixOS user management is expected to delete the =hermes= user and group, which leaves =/var/lib/hermes= owned by a numeric UID until the clean-up. Not verified; check with =ls -ln= after the switch.
