* Intent
Run Kanidm as the single identity store for family web accounts and admin shell accounts, configured declaratively in Nix, on a dedicated Raspberry Pi 4 that is also the home's public entry point. NetBird (task ad910fe5) and later web apps use it for OIDC.

* Summary
*Level:* production · *Tests:* smoke · *Docs:* inline

Draft. Kanidm at =id.emptycannon.eu= on a new =aarch64-linux= edge host, behind an edge Caddy that terminates public TLS with ACME DNS-01 certificates. =emptycannon.eu= DNS moves from GoDaddy to an API-capable provider. Design decisions (Kanidm, NetBird, the Pi 4 edge host, the DNS move) are recorded in =design/home-network-infrastructure.org=.

** Scope
*** In scope
- Move the =emptycannon.eu= nameservers to Cloudflare or deSEC; GoDaddy stays registrar. Dynamic DNS for the public A record.
- New Raspberry Pi 4 NixOS host in =flake.nix= (=aarch64-linux=, SSD root, =nixos-server.nix=), with local break-glass admin access and no MooseFS mount (make the =/mnt/mfs= mount in =nixos-base.nix= optional per host).
- Edge Caddy as the single public entry point: ACME DNS-01 certificates, UniFi forward of WAN :443.
- Kanidm server with =services.kanidm.provision= (people, groups, the NetBird OAuth2 client) and online backups.
- A spike that proves NetBird accepts Kanidm as its IdP before the hardware work.
- Relevant contract: =design/home-network-infrastructure.org= (exposure model, identity direction, roadmap).
*** Out of scope
- The NetBird server and clients (task ad910fe5).
- Kanidm Unix (PAM/NSS) and SSH integration on servers (roadmap Phase 5).
- OIDC for Open WebUI and other web apps, and forward-auth for apps without a login (roadmap Phase 4).
- Changes to the NAS Traefik setup.

** Acceptance
*** Core functionality
- [ ] A NetBird management service accepts a login by a provisioned Kanidm user (spike, before hardware).
- [ ] =https://id.emptycannon.eu= serves the Kanidm login page to an off-LAN device with a publicly trusted certificate.
- [ ] A person declared in =services.kanidm.provision= logs in with a passkey.
- [ ] The NetBird OAuth2 client exists in Kanidm as declared in Nix.
- [ ] An online backup file is written on schedule.
*** Edge cases
- [ ] On the LAN, =id.emptycannon.eu= resolves to the edge host's LAN address and login works while the WAN link is down.
- [ ] A restore from the online backup recovers the provisioned people and groups.
*** Anti-criteria
- [ ] Must not: put the Kanidm admin passwords, provision secrets or DNS API token in the Nix store or git.
- [ ] Must not: make the edge host's login depend only on Kanidm (local break-glass admin and SSH key remain).
- [ ] Must not: change the NAS Traefik configuration.
- [ ] Must not: mount MooseFS on the edge host.

** Decisions
- Decisions shared with the wider network design live in =design/home-network-infrastructure.org=: Kanidm (rejected Authentik, Keycloak, FreeIPA), NetBird, the Pi 4 edge host, and the DNS move.
- Spike before hardware :: NetBird does not list Kanidm as a tested IdP, and Kanidm requires PKCE (=S256=) and =ES256= by default, so prove the pairing in a NixOS VM on an x86 host first.
  Rejected:
  - Build the edge host first: the hardware and DNS work would be wasted if the pairing fails.

** Risks
- Single edge host :: logins and NetBird coordination stop while it is down; local break-glass access and established connections are the fallback.
- Public IdP :: login pages are internet-facing; require passkeys for admins and keep the admin accounts off daily use.
- Slow =aarch64-linux= builds on the Pi 4 :: most packages come from the binary cache; decide the build path before the first deploy (see Open questions).

** Follow-ups
- Kanidm Unix and SSH integration on servers: roadmap Phase 5 in =design/home-network-infrastructure.org=.
